3 Multi-Device Synchronization Architecture (Device X vs Device Y)
Problem Solved: Previously, offline client-side storage caused accounts created on Device X to be isolated, leaving Device Y with missing data. The architecture was upgraded to make Neon PostgreSQL the Single Source of Truth.
Device X (Source Device - Field Operator / Mobile) Origin

1. User signs up / logs in on Device X (Android APK or Mobile Web).

2. Enters Lorry Receipts (LR), trips, fuel expenses, or customer invoices.

3. Application sends authenticated HTTP POST/PUT requests to Render FastAPI.

4. Neon PostgreSQL validates and commits the row transaction in milliseconds.

Result: Data is immediately persisted in the global cloud database.

Device Y (Destination Device - Head Office / Desktop) Synchronized

1. Manager logs into the identical account on Device Y from another city or office.

2. FastAPI issues a verified JWT token tied to the user's primary company ID.

3. Frontend initiates authenticated GET requests fetching latest ERP state.

4. FastAPI executes high-speed indexed SQL queries against Neon PostgreSQL.

Result: 100% identical data, LRs, and balances displayed instantly on Device Y.
